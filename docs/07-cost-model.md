# 07. 비용(TCO) 산정 모델

## 1. 산정 원칙

- **동일 SLA 달성을 전제로** 비교한다. "노드 3대 기준 비용"이 아니라
  "[05-성능 §P2](05-performance-test.md#p2-대시보드-응답-시간-배점-10의-일부)의 SLA(대시보드 p95)와
  [P3](05-performance-test.md#p3-동시성-배점-10)의 목표 동시성을 만족시키는 데 필요한 구성"의 비용을 산정한다.
- 산정 기간은 **3년**으로 고정한다.
- 모든 단가는 출처(클라우드 요금표 URL, 사내 조달 단가표, 산정 시점)를 명시한다.
- 추정이 불가피한 항목은 추정임을 표시하고 **낙관/비관 시나리오를 함께** 제시한다.

## 2. 비용 구성 항목

| 대분류 | 항목 | 산정 방법 |
|---|---|---|
| 인프라 | 연산 노드 | SLA 달성 필요 노드 수 × 인스턴스 단가 × 36개월 |
| 인프라 | 제어 노드 | 대수 × 단가 × 36개월 |
| 인프라 | 네트워크/전송 | 클라우드 egress, 노드 간 전송량 (P6 측정값 기반) |
| 스토리지 | 원본 레이크 | 데이터 크기 × 단가 (두 엔진 공통) |
| 스토리지 | 엔진 전용 사본 | 네이티브 테이블 복제본 크기 × 단가 |
| 스토리지 | 캐시 계층 | 로컬 NVMe 용량 × 단가 |
| 소프트웨어 | 라이선스 | 오픈소스 라이선스 조건 확인 결과 기재 |
| 소프트웨어 | 상용 지원 | 벤더 지원 계약 시 연간 비용 (선택 시나리오) |
| 인력 | 초기 구축 | 구축 M/M × 단가 |
| 인력 | 정상 운영 | 연간 운영 M/M × 단가 × 3 |
| 인력 | 학습/전환 | 교육, 기존 쿼리 마이그레이션 공수 |

## 3. 스토리지 비용 비대칭 처리

> 이 항목을 잘못 다루면 비용 비교가 통째로 왜곡된다.

| 구성 | 저장되는 데이터 | 비용 특성 |
|---|---|---|
| Trino (레이크 직접 조회) | 원본 레이크 1부 | 추가 사본 없음. 캐시 사용 시 로컬 디스크만 추가 |
| StarRocks Track A (외부 카탈로그) | 원본 레이크 1부 + 로컬 캐시 | Trino와 유사 |
| StarRocks Track B (네이티브, shared-nothing) | 원본 + 네이티브 사본(복제본 수만큼) | 사본 수만큼 스토리지 증가 |
| StarRocks Track B (shared-data) | 원본 + 오브젝트 스토리지상 사본 + 로컬 캐시 | 사본 1부 + 캐시 |

Track B로 성능 점수를 얻었다면, **그 구성의 스토리지 비용을 그대로 비용 항목에 반영**해야 한다.
성능은 Track B, 비용은 Track A로 계산하는 혼용은 금지한다.

## 5. 운영 인건비 산정

[06-운영성 테스트](06-operability-test.md) 결과를 M/M로 환산한다.

| 활동 | 산정 근거 |
|---|---|
| 초기 구축 | O-설치 측정 시간 × 실환경 배수(권장 5~10배) |
| 일상 운영 | 모니터링·튜닝·용량 관리 예상 시간/주 |
| 장애 대응 | F1~F6에서 수동 개입이 필요했던 시나리오 수 × 예상 발생 빈도 |
| 업그레이드 | 연 2회 가정 × 롤링 업그레이드 측정 시간 × 배수 |
| 쿼리 마이그레이션 | 기존 SQL 자산 중 [04-기능](04-functional-test.md)에서 미지원 판정된 문법의 비율 |

> 마지막 항목이 실무에서 가장 과소평가된다. 기존 쿼리 샘플 50~100건을 대상 엔진에서
> 실제로 실행해 보고 **수정 필요 비율**을 측정하여 근거로 삼는다.
