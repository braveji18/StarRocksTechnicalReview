# 01. 평가 기준 및 채점 방법

## 1. 채점 원칙

- 모든 점수는 **측정값 또는 체크리스트 판정**에서 기계적으로 산출한다. 주관 점수 항목을 두지 않는다.
- 측정값 기반 항목은 **상대 점수**로 환산한다. 두 엔진 중 우수한 값을 만점으로 두고 상대 비율로 배분한다.
- 판정 불가(측정 실패, 미구현)는 0점으로 처리하고, 사유를 결과표에 기록한다.
- 채점 원시 데이터는 [08-결과 기록 양식](08-result-templates.md)의 표로만 관리한다.

## 2. 상대 점수 환산식

지연 시간처럼 **작을수록 좋은 지표**:

```
점수 = 배점 × (min(A, B) / 해당 엔진 측정값)
```

처리량처럼 **클수록 좋은 지표**:

```
점수 = 배점 × (해당 엔진 측정값 / max(A, B))
```

성능 차이가 10% 이내이면 **동점 처리**한다(측정 오차 범위로 간주). 동점 처리 시 두 엔진 모두 만점을 부여한다.

## 3. 배점 상세

### 3.1 기능 (20점)

[04-기능 테스트](04-functional-test.md)의 체크리스트 항목별로 판정한다.

| 판정 | 정의 | 점수 |
|---|---|---:|
| 지원 | 표준 문법으로 정상 동작 | 2 |
| 부분 지원 | 우회 구문 필요, 제약 존재, 성능 저하 동반 | 1 |
| 미지원 | 문법 오류 또는 기능 부재 | 0 |

카테고리별 가중치:

| 카테고리 | 가중치 |
|---|---:|
| SQL 표준 · Window · 집계 | 5 |
| Join · 서브쿼리 · 옵티마이저 | 4 |
| Materialized View · 쿼리 재작성 | 3 |
| 반정형(JSON/ARRAY/MAP/STRUCT) | 2 |
| 레이크 포맷(Iceberg/Hudi/Delta) | 4 |
| 보안(인증 · RBAC · 마스킹) | 2 |
| **합계** | **20** |

카테고리 점수 = 가중치 × (획득 판정 점수 합 / 해당 카테고리 만점).

### 3.2 성능 (30점)

| 세부 | 배점 | 지표 |
|---|---:|---|
| 단일 쿼리 지연 | 10 | TPC-H 22 + TPC-DS 99 웜 실행 시간 기하평균 |
| 동시성 | 10 | 동시 50 사용자 기준 p95 지연 및 QPS |
| 대용량 처리 | 5 | SF1000 대용량 조인 완주 여부 및 소요 시간 |
| 자원 효율 | 5 | 동일 워크로드 완료 시 총 CPU초 및 피크 메모리 |

> 완주 실패(OOM, 타임아웃) 쿼리는 해당 쿼리 시간을 **타임아웃 값으로 대입**하고 결과표에 실패로 별도 표기한다.
> 실패 쿼리를 평균 계산에서 제외하지 않는다.

### 3.3 운영성 (20점)

| 세부 | 배점 | 판정 방법 |
|---|---:|---|
| 설치 · 초기 구성 | 4 | 소요 시간 및 수동 단계 수 |
| 스케일 아웃/인 | 4 | 무중단 여부, 재분배 완료 시간 |
| 롤링 업그레이드 | 2 | 무중단 여부 |
| 백업 · 복구 | 6 | 백업 대상 완전성, 복구 성공 여부, RTO/RPO |
| 모니터링 · 멀티테넌시 | 4 | 기본 지표 노출, 쿼리 프로파일, 리소스 그룹 격리 실효성 |

### 3.4 확장성 (10점)

노드 3 → 6 확장 시 **선형성 계수** = (확장 후 처리량 / 확장 전 처리량) / 2.

| 선형성 계수 | 점수 |
|---|---:|
| ≥ 0.9 | 10 |
| 0.75 ~ 0.9 | 7 |
| 0.6 ~ 0.75 | 4 |
| < 0.6 | 1 |

무중단 확장이 불가하면 **-3점** 감점한다.

### 3.5 안정성 (10점)

[06-운영성 테스트](06-operability-test.md)의 장애 시나리오 F1~F6 결과로 산출한다.

| 시나리오당 판정 | 점수 |
|---|---:|
| 서비스 무중단 + 실행 중 쿼리 보존 | 1.67 |
| 서비스 무중단 + 실행 중 쿼리 실패 | 1.0 |
| 자동 복구되나 일시 중단 | 0.5 |
| 수동 개입 필요 또는 데이터 손실 | 0 |

6개 시나리오 합산(최대 10점).

### 3.6 비용 (10점)

3년 TCO 상대 비교. `점수 = 10 × (min(TCO_A, TCO_B) / 해당 엔진 TCO)`.
산정 근거는 [07-비용 모델](07-cost-model.md)을 따른다.

## 4. 결격 조건 (Knock-out)

아래에 하나라도 해당하면 **총점과 무관하게 도입 부적합**으로 판정하고, 사유를 최종 권고서에 명시한다.

| 코드 | 결격 조건 |
|---|---|
| K1 | 필수 데이터 소스(사내 표준 레이크 포맷/카탈로그)를 조회하지 못함 |
| K2 | 요구 SLA(예: 대시보드 p95 3초) 를 어떤 구성으로도 달성하지 못함 |
| K3 | 장애 시나리오에서 **데이터 유실**이 발생 |
| K4 | 사내 보안 요건(인증 연동, 권한 모델) 충족 불가 |
| K5 | 라이선스가 사내 정책과 충돌 |

> K1~K5의 구체적 임계값은 착수 단계에서 확정하여 본 표에 채워 넣는다. 착수 이후 변경하지 않는다.

## 5. 완료 조건

- 배점표와 결격 조건 임계값이 이해관계자 서명으로 확정되었다.
- 상대 점수 환산식에 대해 양측 담당자가 동의했다.
